# Текущая архитектура LeadCatch & QuickBook

Проект — TypeScript-монорепозиторий. Один сервер обслуживает множество Telegram-ботов и React-админку через API. Исходное архитектурное задание сохранено [в архиве](archive/system-architecture-specification.md); оно не описывает все последующие изменения.

## Компоненты

- `apps/server`: Node.js, Fastify, grammY и Prisma. Сервер обрабатывает Telegram, API админки и фоновые задания подписок, напоминаний и восстановления доставки.
- `apps/admin`: React и Vite. После сборки это статические HTML/CSS/JavaScript-файлы; они могут обслуживаться веб-сервером на VPS либо отдельным хостингом.
- `packages/contracts`: общие схемы и проверки конфигурации.
- PostgreSQL 18: боты, пользователи, заявки, записи, настройки, подписки, чеки, журнал изменений и постоянные очереди доставки.
- Redis 7: сессии, временные удержания слотов, кеши и вспомогательное состояние.
- `uploads`: файлы чеков и другие сохранённые загрузки. Это отдельные данные, не часть сборки и не содержимое Git.

## Telegram и фоновые задачи

Поддерживаются polling и webhook. В polling сервер сам получает обновления Telegram; публичный входящий webhook-адрес не нужен. В webhook Telegram обращается к опубликованному HTTPS-адресу сервера. Режим определяется `BOT_MODE`.

Сервер должен постоянно работать: помимо запросов пользователей он выполняет фоновые задачи. Простая публикация файлов React не запускает ботов, напоминания и доставку уведомлений.

Для одного токена в polling оставляют один активный обработчик. При переносе старый экземпляр сначала останавливают, затем включают новый.

## Целостность данных

PostgreSQL хранит записи и ограничения пересечения времени. Проверки записи и переноса выполняются после получения транзакционных блокировок; учитываются действующие настройки, серверное время, занятость и расписание. В записи сохраняется согласованная цена, которую не меняет последующая смена прайса.

Новые цены и минимальный срок записи назначаются со следующего рабочего дня по времени Ташкента. До фонового сохранения вступившее изменение учитывается при чтении из базы. Очередь LeadCatch открывает новые заявки, позволяет взять их в работу и сохраняет выполненные/отклонённые в истории.

Уведомления сохраняются в базе вместе с изменениями данных и повторяются после неудачной доставки. При потере ответа Telegram после принятой отправки возможен повтор сообщения.

## Админка и вход

Админка использует относительные адреса `/api/v1/...`. В разработке Vite проксирует их на backend. В production аналогичный маршрут должен обеспечивать веб-сервер либо хостинг админки.

Вход использует access-токен и HttpOnly cookie обновления с `SameSite=Strict`; в production cookie также имеет флаг `Secure`. Предпочтительная схема — админка и её `/api` видны браузеру по одному HTTPS-адресу. Секреты сервера не передаются в сборку React.

## Развёртывание

Производственные Dockerfile, Compose, HTTPS и расписание резервного копирования ещё предстоит настроить для выбранного хостинга. Наличие `.dockerignore` исключает лишние данные из будущего контекста сборки, но не означает готового Docker-развёртывания. Порядок подготовки описан в [руководстве размещения](deployment.md).
