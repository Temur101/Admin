# Приёмка обновления на ноутбуке

Автоматические проверки этапов 1–6 выполняются на отдельных PostgreSQL/Redis. Подключение к реальному Telegram и данные ноутбука проверяются отдельно. Веб-сервер в интернете для polling не требуется.

## Обновление

1. Остановить старые процессы сервера и ботов. Сохранить резервную копию PostgreSQL, папки uploads и исходного `.env` в защищённом месте. Сохранить прежний `TOKEN_ENCRYPTION_KEY`: он нужен для расшифровки уже подключённых ботов.
2. Получить ветку исправлений `codex/security-readiness-fixes`. Проверить, что локальные изменения не потеряются при переключении.
3. Из корня репозитория выполнить:

```sh
pnpm install --frozen-lockfile
pnpm --filter @lcqb/server prisma:generate
pnpm --filter @lcqb/server prisma:migrate:deploy
pnpm build
```

4. Для проверки настоящих ботов локально использовать polling и реальный транспорт (`BOT_MODE=polling`, `USE_MOCK_TELEGRAM=false`). Значения секретов не отправлять в чат.
5. Запустить сервер и админку в двух терминалах:

```sh
pnpm dev:server
pnpm dev:admin
```

6. Открыть админку, проверить подключение ботов и `http://127.0.0.1:8000/health/ready` (или настроенный PORT). Адрес localhost доступен только на том устройстве, где запущен сервер.

## Telegram: владелец и обычный клиент

Использовать тестовые боты и контролируемые аккаунты. Для каждого сценария записать результат и примерное время. Не использовать реальные клиентские записи для проверки отмены и блокировок.

1. LeadCatch: клиент проходит опрос RU/UZ, отправляет телефон, подтверждает итог; владелец получает одну заявку с правильными ответами.
2. QuickBook: клиент создаёт запись, переносит её из «Мои записи», отменяет; владелец получает соответствующие уведомления, время освобождается.
3. Владелец вручную записывает другого клиента: бот спрашивает имя и телефон этого клиента; запись отмечена как ручная. Отмена ручного ввода освобождает удержание времени.
4. Владелец закрывает день с существующей записью: сначала получает предупреждение и отдельную кнопку подтверждения. Клиент и STAFF не могут управлять блокировками.
5. После смены цены или расписания следующий клиент видит новое значение без перезапуска. Некорректные часы не сохраняются.
6. Имя с символами `<`, `>` и `&` отображается как текст. Длинный список записей отправляется частями. Истёкшая подписка маскирует контакты.
7. Текстовый/фото-чек остаётся на проверке и не открывает доступ. После одобрения подписка продлевается один раз; отклонение не снимает независимо оплаченный срок.
8. При недоставленном уведомлении проверить диагностику и ручной повтор после восстановления связи. После переноса проверить напоминание на новом времени (за час до записи).

Результат живой приёмки пока не подтверждён. Публикация на VPS, HTTPS и открытость портов проверяются при появлении настоящего серверного развёртывания.
