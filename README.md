# LeadCatch & QuickBook

Платформа управления Telegram-ботами с общей React-админкой:

- **LeadCatch** — опросы, заявки, очередь обработки и история.
- **QuickBook** — онлайн-запись, перенос, отмена, расписание, цены и уведомления.

## Состав проекта

| Папка                | Назначение                                                |
| -------------------- | --------------------------------------------------------- |
| `apps/server`        | Сервер ботов, API админки и фоновые задачи                |
| `apps/admin`         | React-админка                                             |
| `packages/contracts` | Общие схемы и проверки                                    |
| `apps/server/prisma` | Схема и вся история миграций PostgreSQL                   |
| `scripts`            | Проверки кода и вспомогательные средства разработки       |
| `docs`               | Актуальные инструкции, результаты проверок и архив планов |

Нужны Node.js, pnpm, PostgreSQL 18 и Redis 7. Подробности: [локальная разработка](docs/development.md).

## С чего начать

1. Прочитать [архитектуру](docs/architecture.md).
2. Для ноутбука использовать [инструкцию локальной разработки](docs/development.md) и `.env.example`. Секреты хранить в локальном `.env` вне Git.
3. Для сервера сначала выбрать схему по [руководству размещения](docs/deployment.md). Админку можно разместить на том же сервере или отдельно, например на Vercel.
4. Перед обновлением сохранять базу, `uploads` и исходный ключ шифрования токенов; после обновления проводить [живую приёмку](docs/local-acceptance.md).

## Проверки

`pnpm verify` проверяет типы, линтер, зависимости, неиспользуемый код, границы тестового транспорта, тесты и сборку. Серверным интеграционным тестам нужны отдельные PostgreSQL и Redis. Их адреса задаются через `TEST_DATABASE_URL` и `TEST_REDIS_URL` и должны отличаться от рабочих сервисов. Перед первой проверкой после получения исходников нужно сгенерировать Prisma Client и собрать `packages/contracts`; порядок описан в документации разработки.

## Развёртывание и данные

Чистый репозиторий и успешные автоматические проверки не означают настроенный сервер. Docker-развёртывание, HTTPS, резервные копии и наблюдение за выбранным VPS настраиваются отдельно. В текущем репозитории пока нет готовых Dockerfile/Compose и автоматического расписания бэкапов.

`node_modules`, сборки, база, загрузки, `.env` и резервные копии не должны попадать в Git. Демоматериалы и старые результаты аудита исключены из текущего дерева с сохранением истории. Миграции, тесты и исходный код сохранены.
