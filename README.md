# LeadCatch & QuickBook Platform

Мультитенантная платформа для управления Telegram-ботами двух типов (LeadCatch — квиз-захват лидов, QuickBook — онлайн-запись на услуги) под управлением единой React-панели.

## Стек технологий

- **Backend:** Node.js (Fastify, grammY, Prisma)
- **Database:** PostgreSQL 18
- **Cache & Locks:** Redis 7 (Memurai Developer)
- **Frontend:** React 19 (Vite, Tailwind CSS, Lucide Icons)
- **Monorepo:** pnpm workspaces, TypeScript strict

## Локальное окружение (Windows)

### 1. Запуск сервисов

Сервисы запускаются локально без конфликтов и без прав администратора:

- **PostgreSQL 18** работает на порту `5433`:
  ```powershell
  # Запуск сервера БД вручную (если остановлен):
  & "F:\Postgres\bin\postgres.exe" -D "f:\Рабочий стол\AAA\.local_data\postgres"
  ```
- **Redis / Memurai 7** работает на порту `6379`:
  ```powershell
  # Запуск Redis:
  & "f:\Рабочий стол\AAA\tools\memurai\Memurai\memurai.exe" --port 6379 --maxmemory 64mb
  ```

### 2. Подключение к БД через терминал

```powershell
# Подключение к dev-базе под пользователем приложения lcqb_app:
$env:PGPASSWORD = "<пароль_из_.env>"
& "F:\Postgres\bin\psql.exe" -U lcqb_app -h 127.0.0.1 -p 5433 -d leadcatch_quickbook_dev

# Проверка Redis:
& "f:\Рабочий стол\AAA\tools\memurai\Memurai\memurai-cli.exe" ping
# Ответ: PONG
```

## Скрипты разработки и сборки

### Мастер запуска в админке

В разделе «Боты» нажмите «Подключить бота» и пройдите шаги: клиент → задача → шаблон → настройка → проверка → запуск. Клиента можно создать прямо в мастере. Новый бот остаётся приостановленным до явного запуска; пробный период начинается при подключении, его точная дата окончания показана в мастере.

Перед проверкой сохраните настройки в редакторе. Сервер проверяет сценарий, подписку, доступность Telegram и готовность обработки сообщений, а перед запуском повторяет проверку. Если включение не удалось, прежний статус бота восстанавливается. После запуска откройте диалог как клиент и передайте владельцу ссылку администратора.

«Продолжить позже» позволяет вернуться к мастеру из списка или карточки бота. Выбранные параметры подключения и текущий шаг сохраняются в этом браузере отдельно для каждого администратора; токен не сохраняется в черновике и до подключения вводится заново. Настройки редактора сохраняются на сервере кнопкой «Сохранить»; несохранённые изменения защищены предупреждением при выходе. На другом устройстве уже подключённый бот доступен в списке, но шаг мастера начинается с настройки.

### Визуальная настройка сценария

В редакторе заявок можно создать связанную цепочку из трёх вопросов, заменить тексты на русском и узбекском и выбрать следующий шаг для каждого ответа. Номера переходов соответствуют карточкам вопросов; изменение порядка карточек сохраняет переходы. Предпросмотр позволяет пройти диалог на обоих языках. Проверка выявляет циклы, недоступные вопросы и пути короче трёх или длиннее пяти вопросов, включая раннее завершение отдельной ветки.

В редакторе записи доступны названия категории для клиента, произвольная длительность услуги от 5 до 480 минут, цена, рабочие дни, часы, перерыв и дублирование услуг или ресурсов. Режим «Все услуги» включает услуги, добавленные позже; при ручном выборе нужна хотя бы одна услуга. Удаление услуги очищает её назначения. Если у ресурса не останется выбранных услуг, он переключается на все услуги; это поведение указано в подтверждении удаления.

Предпросмотр записи показывает время по выбранному дню, услуге и ресурсу с учётом длительности и перерыва. Он не учитывает реальные брони и текущую дату и не создаёт запись. Ошибки показаны до сохранения; сервер повторяет проверки при сохранении и запуске. Режим JSON использует те же проверки.

### Проверенные версии окружения

- **Node.js:** `>= 20` (проверено на `v24.15.0`)
- **pnpm:** `>= 9` (проверено на `v9.15.4`)
- **PostgreSQL:** `>= 16` (проверено на `v18.0` с расширением `btree_gist`)
- **Redis:** `>= 7.0` (проверено на Memurai `v4.1.4 / Redis 7.0`)

### Порядок генерации, сборки и запуска

```bash
# 1. Установка зависимостей
pnpm install

# 2. Генерация Prisma Client
pnpm --filter @lcqb/server exec prisma generate

# 3. Применение миграций БД
pnpm --filter @lcqb/server exec prisma migrate deploy

# Проверка интерфейса и диагностики подключения без PostgreSQL/Redis
pnpm test:admin

# 4. Проверка качества всего репозитория (нужны отдельные тестовые БД и Redis)
pnpm verify

# 5. Сборка всех пакетов (contracts, server, admin)
pnpm build

# 6. Запуск сервера в production режиме
pnpm --filter @lcqb/server start
```

### Dev-режим

```bash
# Запуск бэкенда в dev-режиме
pnpm dev:server

# Запуск React админки в dev-режиме
pnpm dev:admin
```
